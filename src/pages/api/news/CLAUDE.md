### Newsboard
- **Daily AI fetch**: Vercel cron (6 AM daily) triggers `/api/news/fetch-daily` which fetches from 9 RSS feeds + NewsData.io API
- **RSS feeds**: Tagesspiegel, Berliner Zeitung, Berliner Kurier, nd-aktuell, taz, Kiez und Kneipe, Schillerpromenade, Facetten Neukölln, Pro Schillerkiez
- **GPT-4o scoring**: All articles scored for Berlin/Neukölln relevance (threshold 70/100, max 20/day)
- **Ordering (updated 2026-09-22)**: Articles sort `{ fetchDate: -1, publishedAt: -1, aiRelevanceScore: -1, [sortBy]: …, _id: -1 }` — day first, then the article's real publish time inside the day, `aiRelevanceScore` only a tiebreak. User-submitted articles get `fetchDate` set at admin approval time, not submission time. The former „user-submitted first" rule (`source: -1`) is dropped — a submission sorts by its publish date like everything else now. Before this day every item of one 6 AM cron run shared the same `fetchDate`, so the GPT score alone ordered a day and a 4-day-old score-90 item could outrank a 4-hour-old score-85 one; see `src/lib/newsboard/newsFormat.ts`'s `pickLead()` for the matching lead-card fix. `src/lib/landing.ts`'s Kurier-top-3 teaser has its OWN pick (latest `fetchDate` issue, top 3 by `aiRelevanceScore` — unchanged, still score-ordered) — deliberately left alone, see „Does NOT do" in `docs/superpowers/plans/2026-09-22-newsboard-kiez-cards-and-order.md`.
- **Auto-approve**: AI-fetched articles are auto-approved (no moderation needed); only user-submitted news goes through moderation
- **Degraded-scoring alert**: GPT scoring failure (e.g. OpenAI credits exhausted) falls back to score 50 — below the 70 threshold — so the cron "succeeds" daily while saving nothing (real incident Aug 1–4 2026: board starved 4 days, zero errors). `scoreArticlesWithGPT` returns `{ scored, degraded }`; on `degraded` the handler sends `Sentry.captureMessage` + `flush(2000)` before returning (flush is mandatory — success responses aren't flushed by middleware, Vercel's freeze would eat the event).
- **Image pipeline**: RSS media:content → enclosure → description `<img>` → og:image scrape → placeholder fallback
- **Dedup**: By sourceUrl + title, with unique index on title
- **HTML entities decoded at ingest (2026-09-08)**: feeds and pasted headlines deliver entity-encoded punctuation (German quotes as `&#8222;`/`&#8220;`, dashes as `&ndash;`), and the newsboard renders titles as escaped TEXT — so anything left encoded showed up literally on prod. All three ingest paths now run `decodeHtmlEntities()` (`src/utils/decodeHtmlEntities.ts`, dependency-pure: numeric decimal + hex + the DE/EN named set, `&amp;` decoded LAST so a double-encoded reference decodes exactly one level): `fetch-daily` (RSS `title` was completely raw; the old inline `description` chain knew five named entities and ran `&amp;` first), `submit`, and `preview` (whose local helper also skipped numeric entities). Decode happens BEFORE dedup-by-title so a decoded feed title matches a decoded stored title. Never decode at render. Already-stored rows: one-shot `scripts/backfill-news-entities.ts` (default dry-run with before/after, `--apply` to write; decodes title/titleEN/description/aiSummary; one level deep per pass; some feeds double-encode, so iterate dry-run→apply until the dry-run reports 0 — the 2026-09-09 prod run took two passes for 98 titles).
- **Link preview for the submit form — `GET /api/news/preview?url=` (hardened + reconnected 2026-09-21)**: the server fetches an address a member typed, so it is an SSRF surface. Until that day it fetched ANY valid URL (any scheme `fetch` takes, any port, IP literals, blind redirects, whole body) and nothing in the UI called it — the kiosk submit form had dropped the auto-fill in the June migration. Rules now: https only, default port, no credentials, no IP literals in any spelling, no single-label / `.local` / `.internal` names (pure `checkPreviewUrl()` in `src/lib/newsboard/previewUrlGuard.ts`, 6 tests: `npx tsx --test src/lib/newsboard/previewUrlGuard.test.ts`); every resolved address must be public (`isPrivateAddress()`, `node:dns` `lookup(…, { all: true })` in the endpoint) for the first address AND every redirect hop (`redirect: 'manual'`, max 3); HTML only (`not_html`), first 512 KB, 8 s; 30 lookups per member per hour (`newsprev:<userId>` in `rateLimits`); static error codes (`url_not_allowed` 400, `throttled` 429, `fetch_failed`/`not_html` 422, `timeout` 504) — nothing about the target leaks back; returned `image` is absolute https or `''`, texts are cut to the form's limits (200/1000/100). Accepted residual: DNS rebinding between our lookup and `fetch`'s own (pinning needs a custom undici dispatcher; no private network behind a Vercel function). Extend the guard rather than loosening it — same stance as the push-subscription allowlist. Form side: `NewsSubmitInner.svelte` — the link field is FIRST, paste/change triggers one lookup per address and fills only EMPTY fields (title, description, source name, image), status line `news.submit.url.{hint,loading,filled,failed}`; the image is the article's own `og:image`, hot-linked like the daily fetched news (the member can remove it or upload one). Probe (DEV ONLY — spends budget, fetches third-party pages): `scratchpad/news-preview-probe.cjs` (21 checks incl. ten hostile addresses, a public name resolving to 127.0.0.1 and a redirect into a private address).
- **Bookmarks**: Server-side persistence via `savedNews` collection (localStorage fallback for logged-out users)
- **Filters**: Date range tabs (7d, 30d, 3m, 6m, 1y, Archive), live search with 300ms debounce
- **Archive**: Articles older than 1 year shown in Archive tab with "Archived" badge
- Key config: `vercel.json` (cron schedule), `src/pages/api/news/fetch-daily.ts` (RSS feeds, thresholds)
- **Piggy-backed air-logger watchdog** (Aug 2026): `fetch-daily.ts` calls `checkAirLoggerFreshness()` (`src/lib/kiez/airFreshness.ts`) right after the cron-secret check — nothing to do with news. It rides this cron because Vercel-NATIVE schedules hit the deployment directly and so can't be broken by a domain/alias change, unlike the GitHub-Actions air logger (which a 308 from the retired `*.vercel.app` origin silently killed for two days). Fires `Sentry.captureMessage` + `flush(2000)` when the `schillerkiez_air_log` collection has had **zero** rows in 24h. Zero (not "a few hours") is deliberate: BLUME publishes hourly and healthy days land 17–21 readings, so multi-hour gaps are normal and a tight threshold would cry wolf. It is best-effort and never throws — a watchdog must not fail its host cron — but it reports its own failure rather than swallowing it. Placed BEFORE the early returns so a news-side outage can't also blind the air check.
