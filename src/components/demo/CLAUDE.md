### Demo deployment — demo.mahalle.digital (2026-10-26, `c3727b34`)
A read-only copy for recruiters and hiring managers, never prod: the git branch `demo` (always a commit of `main`, released by hand with `git push origin main:demo`) is built as a Vercel PREVIEW (no crons, no mail/push/Telegram transport) and served on the branch domain `demo.mahalle.digital`; branch-scoped preview vars give it `DEMO_MODE=1`, the third database `mahalle-dev-demo`, its OWN `NEXTAUTH_SECRET`, its own `CRON_SECRET` (= repo secret `DEMO_CRON_SECRET`) and blank Sentry vars. Code: `src/lib/demo/` — `demoRules.ts` (pure, tested: `isDemoEnabled` = flag `'1'` AND db name `/dev/i`; `decideDemoRequest` = GET/HEAD/OPTIONS allowed, every other method refused unless the normalised path is exactly `/api/auth/csrf`, `/api/auth/callback/demo` or `/api/auth/signout`; a demo session's GET on `/api/admin/errors` is a blocked read), `demoMode.ts` (server: `isDemoDeployment()`, `demoRefusal()` 403 `{ error: 'demo_read_only' }`, `demoBlockedRead()` 200 `{ enabled: false, demo: true }` so the admin card shows „nicht konfiguriert", not a warning), `demoProvider.ts` (second Credentials provider id `demo`, role `member|admin` → `findOne({ handle, demo: true })`, constructed ONLY when the flag holds), `startDemo.ts` (browser: csrf → form POST to `/api/auth/callback/demo`, parses Auth.js's `{ url }` for `?error=` — auth-astro routes only the literal `credentials` id to the callback path). Middleware: the write refusal sits ABOVE the static-asset skip (like the cross-site check, so a dotted dynamic path cannot slip past), the blocked read after the session. **Three locks that must stay:** (1) the `jwt` callback returns `null` for any token with `demo: true` on a NON-demo deployment — a demo admin's cookie copied onto mahalle.digital would otherwise be a working prod admin session whenever the Auth secret is shared (Opus review, critical); (2) the credentials `authorize` refuses a user doc without a string `password` (demo users carry `password: null`; also keeps bcrypt from `undefined`); (3) `/api/admin/errors` answers `{ enabled: false }` itself on a demo deployment. UI: `src/components/demo/` (`DemoDoor.svelte` shared by login + register — nested island, its classes `.dd-*` live in `global.css`; `DemoBanner.svelte` mounted by KioskLayout + AdminLayout for `session.user.demo`; `DemoHead.astro` = robots noindex meta in every layout head incl. logout), the landing's CTA block swaps to the demo block under the `demo` prop; i18n keys `lnd.demo.*`, `auth.demo.*`, `demo.banner*` are DRAFT. Data: `scripts/seed-demo-db.ts` (interlock: db name must contain BOTH `dev` and `demo`; dry-run default, `--write`; FIXED ObjectIds `64656d6f…01–08` so the nightly reseed never orphans a 7-day demo session; `blogAnnouncements` pre-filled with every `src/content/blog/*.mdx` id so no fan-out ever runs; `--copy-kiez` copies the five `schillerkiez_*` collections from `KIEZ_SOURCE_URI` (env, never argv; the owner authorised a nightly read-only copy from PROD); `news` never touched — the demo runs its own daily fetch) + `.github/workflows/demo-reseed.yml` (04:00 UTC: checkout `demo`, reseed with `DEMO_MONGODB_URI`, copy from `secrets.MONGODB_URI`, ring `demo.mahalle.digital/api/news/fetch-daily` with `DEMO_CRON_SECRET`; errors print name + code only). Verified 2026-10-26 on the local prod build: `scratchpad/demo/probe.cjs` 23 checks in demo mode, 6 flagless (password login still works, no provider, no banner, no meta), 3 with the prod database NAME on an unreachable host (no provider, password form) — one build serves all three because `import.meta.env.MONGODB_URI` compiles to a RUN-TIME `process.env` read in the server bundle (ONLY because the variable exists at build time — a variable absent at build is inlined as `undefined`, learned 2026-11-02 with `RESEND_WEBHOOK_SECRET`; read such a variable via `process.env` directly) (so the probe sets the URI on the SERVER command; the branch var applies at request time).
