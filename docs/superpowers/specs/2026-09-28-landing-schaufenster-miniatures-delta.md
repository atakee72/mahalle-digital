# Schaufenster delta: the frames are faithful miniatures of the real screens

**Date:** 2026-09-28 · **Status:** draft for the owner's review · **Amends:** `2026-09-28-landing-schaufenster-design.md` (everything not named here stays as built on `feat/landing-schaufenster` @ a1c927e5)

## 1. What changes and why

The owner's picture of the strip is the canvas direction 1: each frame IS the top of the real section page, as a member sees it on a phone (bar with its discs, the page's kicker line, the carved title, the count line, the filter pills, the first real card), with today's content in it. What was built shows a replica bar, the title and one pared-down card, and leaves the lower half of each frame empty. The delta rebuilds the six frame bodies as faithful miniatures. The strip, its motion, the fallback images, the privacy rules, the header line and the data cache mechanism stay.

## 2. Mechanism: one 390 px replica per section, scaled into the frame

Each live frame body is authored at the real phone size, `390 × 650` CSS px, using the section's own sizes, fonts and tokens (14 px body, 28 px carved title, 54 px bar, 16 px insets, the same pill and card recipes), and then scaled into the frame with `transform: scale(<frameInnerWidth> / 390)` and `transform-origin: top left` inside a box that reserves the scaled height (`aspect-ratio` on the frame stays `3 / 5`, the inner box is `390 / 650` so nothing shifts). Desktop frames scale by 194 / 390 ≈ 0.497, phone frames by 230 / 390 ≈ 0.59 (the 3 px border subtracted). Text at that scale reads like the screenshots do today. `transform` on the inner box is fine here: the frame contains no fixed or sticky descendants.

The fallback frame keeps showing the full-frame WebP (it already is a 390-px screenshot scaled the same way).

Replica rules:
- **Same recipes, no imports of the real islands.** The miniature is plain markup + `.lnd-sf-*` styles in `LandingPage.svelte` (the nested-island CSS rule still holds). Copy the exact class values from the real components (`KioskNav.svelte` bar anatomy, the section title blocks, `ForumPostCard`, calendar month grid, `ListingLead`, `NewsMasthead`, `KzAirStrip`/`KzTitleBlock`, blog masthead) and reuse their i18n keys — no new copy where the page already has a key.
- **Bar:** the real anatomy — logo disc with the paper ring, DE/EN pill (DE active), search disc, bell disc, avatar disc — all decorative (`aria-hidden`), no real controls. The avatar disc is an empty paper disc (no face: the visitor has no account).
- **Kicker line:** the page's own, with the live Berlin date and time (`FORUM · MONTAG 28. SEP. · 19:32` etc.), formatted as the page formats it.
- **Everything below the title is live or omitted.** Every number the real top shows must be real (project rule); if a number cannot be computed cheaply it is left out, never invented. Author rows are replaced by the kind chip + time (privacy rule).
- **Height:** whatever does not fit into 650 px is clipped by the frame, like a phone screen cuts the page. The first card must be at least half visible at 650 px on every section.

All new cache fields are computed inside `compute()` in `src/lib/landing.ts`, fail-soft like the rest, and grouped under `schaufenster` (the reader treats missing fields as absent → those lines are omitted, never zeroed; a wholly empty section still falls back to the screenshot). The blog fields come from `index.astro` (build-time collection), as today.

## 4. Privacy (unchanged, restated for the new elements)

No member name, handle, avatar or e-mail anywhere; the forum card's author row becomes chip + time; the event dots carry no titles; the listing lead shows no seller; the Kiez frame is public data. The blog byline is editorial and stays. Warning-labelled content stays excluded. The consent sentence on the privacy page still holds (titles, tags, first photo).

## 5. Performance and CLS

Every miniature is SSR-rendered inside a fixed box, so the layout is stable; the only images are the ones the frames already load (listing photo, Kurier photo, blog cover) plus the forum card image when present (lazy, `cloudinaryFit` 480). The month grid is 42 spans; the air strip is text. The `transform: scale()` inner box is composited once; no `filter`.

## 6. Testing

- `frames.test.ts` grows with the new fields (present → line rendered, absent → line omitted, counts at 0 render „0", never hidden — the page shows zeros too).
- Probe additions at both widths: each live frame's first card is at least half visible (its top < 650 px in replica coordinates), the month grid shows the current Berlin month name and today's disc, the Kurier issue number equals `computeIssueNumber(now)` printed by the SSR, the forum count line has three numbers, and the screenshots for the owner.
